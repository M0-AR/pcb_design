01 / OVERVIEW

A board is a system, not a picture.

Most beginners see a green rectangle. Engineers see a power tree, a return path, a timing budget, and a manufacturing contract. The studio makes those layers visible, then gives you a way to act on them.

Learn by doing

Orbit the board, select a part, trace a net, then route it yourself. Every interaction maps to a concept you can name and defend.

Design with constraints

A typed specification validates dimensions, references, pads, nets, and BOM before a single file is exported. Constraints are the design.

Analyze with evidence

Three-phase scenarios produce RMS, THD, severity, and a documented heuristic, not a black-box score. Every number has a method behind it.

Use an open board and a reproducible lab instead of slides.

    06 / RESEARCH

    Transparent by design.

    The analytics model is small enough to inspect and reproducible enough to test. The goal is not a black box; it is a shared language between layout, power, and manufacturing.

    Method

    A balanced three-phase voltage is generated at 10 kHz, 50 Hz, and 311 V peak. A fault is applied after a configurable instant. The detector compares the weakest short window in each phase against the nominal RMS.

    Balanced phase voltage v_a(t) = V_p sin(2πft), v_b(t) = V_p sin(2πft - 120°), v_c(t) = V_p sin(2πft + 120°)
    RMS V_rms = sqrt((1/N) Σ v[n]²)
    Total harmonic distortion THD = sqrt(Σ H₂..H₁₀²) / H₁
    Windowed severity severity = 1 - min_w(V_rms,w / V_rms,nominal)

    Validation and limits

    Synthetic tests cover nominal, open-phase, short-circuit, late-fault, and invalid-input cases. The demo bundle builds in CI without KiCad.

    • Round-trip tests preserve board specifications through JSON and regenerate the BOM.
    • Next: hardware-in-the-loop validation with a relay test set and a calibrated power-quality recorder.
    • Next: expert review against IEC 61000-4-30 measurement classes.
    • No electromagnetic, thermal, or mechanical solver is included.
    • Footprints and traces are simplified reference geometry, not fabrication-ready artwork.
    • Fault detection is a transparent RMS heuristic, not a trained classifier or a certified relay.
    • The game teaches routing intuition; it is not a substitute for DRC, DFM, or expert review.
    • Market figures are third-party estimates, quoted with dates and caveats.

    Reproduce the study

    The same seed, window, and fault timing produce the same report.

    One command pcb-design analyze --fault short --phase B --seed 7 --output analysis.xlsx --report report.md
    Full demo pcb-design demo --out-dir demo-output
    • Inputs: 10 kHz, 50 Hz, 311 V peak, fault at 40 ms, seed 7.
    • Outputs: waveform sheets, summary, field reference, Markdown report.
    • Tests: 40+ automated checks, including late-fault detection and JSON round-tripping.
    07 / START

    Run it in under a minute.

    Clone, install, and build the full demo. KiCad is optional; the core workflow is not. The browser studio is static and deploys on GitHub Pages.

    bash / zsh 
    # 1. clone the repository
$ git clone https://github.com/M0-AR/pcb_design.git
$ cd pcb_design

# 2. install the package and development tools
$ python -m pip install -e ".[dev]"

# 3. build the KiCad-free demo bundle
$ pcb-design demo --out-dir demo-output

# 4. optional: export a .kicad_pcb with KiCad's Python
$ pcb-design board --output board.kicad_pcb
    python -m pip install -e ".[dev]"
